# S75 エージェントによる知識の取り込み Implementation Plan

**Goal:** MCP に接続したコーディングエージェントが、`sync_status` → `knowledge_pull`（サーバが署名した SyncPlan）→ 同梱の実行スクリプト `speclino_apply.py` で、チームの知識（スキル・AGENTS.md / CLAUDE.md の管理区画・仕様の写し・lock）を安全に取り込み、作業の PR と一緒にコミットできるようにする。CLI の `speclino sync` も同じ計画と実行スクリプトを使う。

**Architecture:** `src/speclino/sync_apply.py`（標準ライブラリだけ・Python 3.10 以上。パスの許可リスト・管理区画の分割・事前確認・段階書き・巻き戻し。正本）→ `plugins/speclino/scripts/speclino_apply.py`（同じバイト列）。サーバ側は `services/knowledge_sync.py` が `render_files` → `verified_previous_lock`（署名・ワークスペース・リポジトリ ID）→ `issue_lock(absent=…)` → `plan_writes`（純粋）→ 署名、を `build_plan` にまとめる。REST（`POST /api/sync/bundle`）と MCP（`knowledge_pull`）が同じ `plan_for_project` を呼び、`knowledge_fetches` に記録する。ゲートは `assess_lock` に `absent` の照合を足す。

**Tech Stack:** Python 3.12（実行スクリプトは 3.10 互換）/ pydantic / FastAPI / MCP（`mcp.server.MCPServer`）/ typer / PostgreSQL。

設計の根拠: `design/2026-10-07-agent-sync.md`（A1–A11、3–5 章は拘束）、`design/2026-10-05-team-knowledge-registry.md` 7–8 章。

## 決めたこと（設計の細部）

| 項目 | 決定 |
| --- | --- |
| SyncPlan の形 | `{schema_version, workspace, repo_full_name, github_repo_id, bundle_generation, ops, lock, key_id, signature}`。署名は `signature` 以外の正規 JSON を `bundle_signing.sign`。`repo_full_name` は remote との照合用（数値の ID は remote から推定できないため） |
| op | `write{path, content, sha256, expected_sha256?}`・`set_managed_block{path, inner, generation, expected_inner_sha256?}`・`remove_managed_block{path, expected_inner_sha256}`・`delete{path, expected_sha256}`。ハッシュは lock と同じ（LF に寄せた本文の `sha256:<hex>`） |
| 衝突（A5） | `write` の先に別の内容のファイルがあれば止まる。ただし `expected_sha256`（検証済みの前回の lock がそのパスに記録したハッシュ）と一致すれば上書き。区画も同じ（`expected_inner_sha256`）。新しい内容と同じなら「変えなかった」 |
| 削除（A5） | `delete` / `remove_managed_block` は検証済みの前回の lock にあって今回無いパスだけ。期限切れの lock も署名が合えば根拠にする（本物なので）。`expected_*` と違えば止まる（手で直したファイルを消さない。ゲートで UNKNOWN になる状態を作らない） |
| `absent`（A6） | 新しい lock の `absent: [path]`（削除・区画の除去の対象）。空のときは署名の対象から外す（欄の無い古い lock の署名を保つ）。ゲートは `absent` のファイルが無い・区画が無いことを照合し、残れば UNKNOWN |
| 実行スクリプトの結果 | JSON `{ok, exit_code, bundle_generation, written, deleted, unchanged, reason}`。終了コード 0 / 2（前提が崩れて何も書いていない）/ 1（予期しない失敗、元に戻した） |
| 実行スクリプトと lock | `lock.files` = `write` の `sha256` と区画の `inner` のハッシュ、`lock.absent` = 削除の対象、と一致しなければ止まる（計画と食い違う lock を書かない）。lock は最後に書く |
| remote の照合 | `.git`（ディレクトリか worktree の `gitdir:`）の `config` の `remote "origin"` が github の URL のときだけ `owner/name` を `repo_full_name` と比べる（大文字小文字を区別しない）。推定できなければ確かめない |
| 共有 | `validate_rel_path`・`split_managed`・`merge_managed`・`remove_managed`・`file_hash` と上限・置き場の定数は `sync_apply` を正本にし、`knowledge_sync` はそれを使う（二重に書かない）。`SyncRejected` = `sync_apply.PreconditionFailed` |
| REST | `POST /api/sync/bundle`（body `{repo_id, lock_json?}`）が SyncPlan を返す。旧 `GET` と `SyncPayload` は廃止（利用者は同じパッケージの CLI だけ） |
| MCP の上限（A10） | `knowledge_pull` は計画の JSON が 2MB を超えれば ToolError（`speclino sync` を案内）。記録はしない |
| `sync_status`（A8） | `lock_json` 省略可、`local_hashes` / `managed_inner`（`{path: sha256}`）を受け、`pull_needed` と `reasons`（`no_lock` / `invalid_lock` / `expired` / `other_repo` / `members_changed` / `policy_changed` / `files_modified`）を足す。既存の `stale` などの欄は保つ |
| `write_bundle` | 廃止。テストと CLI は `build_plan` / `plan_writes` → `apply_plan` に移す |
