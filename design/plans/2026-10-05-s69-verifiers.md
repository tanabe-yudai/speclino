# S69: 決定的な規約の検査器 Implementation Plan

**Goal:** 規約の検査器を 4 つ追加し、`api.error_format` を拡張する（spec `design/2026-10-05-team-knowledge-registry.md` 6.1）。

**方針:** 既存の `Verifier` プロトコルに従い、対象は import せず `ast` / `json` / `yaml` だけで読む。verdict は VERIFIED_IN_SCOPE / VIOLATED / UNKNOWN のみ（REVIEW は出さない）。Finding は `<rule.id>:<path>` を requirement_id とし、既存の検査器と同じ形にする。解析できないものは UNKNOWN（偽の VERIFIED を出さない）。

**パラメーター:** `src/speclino/domain/policy_params.py` に検査器ごとの pydantic モデル（型のみ、未定義キーは拒否）。各検査器は `rule.verifier.params` をそのモデルで検証し、不正なら `ValueError`（pydantic の `ValidationError` は `ValueError` の派生）を送出する。

**登録:** `VerifierRegistry` 自体は登録表を持たず、`services/check_pipeline.py` の `_policy_registry()` が登録するため、新しい検査器はそこに足す。
