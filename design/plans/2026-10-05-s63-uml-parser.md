# UML parser と旧形式の入口 Implementation Plan（S63）

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 人が読む Markdown（Mermaid の厳格な部分集合＋要求の表）と旧形式の Spec IR を、決定的に `CompiledSpec`（Task 0 の `domain/uml.py`）へ変換する。対応しない・紛らわしい入力は span つきのエラーにし、推測も読み飛ばしもしない。

**Architecture:** `spec/uml/` に置く。Markdown からコードブロックと要求の表を切り出し（`markdown.py`）、行ごとに全域の字句解析（`lexer.py`。どんな文字列もトークン列にする）をかけ、図ごとの手書きの再帰下降（`class_diagram.py` / `sequence.py` / `state.py` / `activity.py`）が各トークンを `ir` / `ignored` / `error` に分類する。ガードは `guard.py` が `domain/expr.py` の `Expr` へ変換する。`compile.py` が図をまたぐ解決（列挙・要求の参照・level・旧形式・ハッシュ）を行い、分類されなかったトークンが 1 つでもあればエラー（全か無か）。`render.py` は IR から正規形の Markdown を作る。

**Tech Stack:** Python 3.12、pydantic（Task 0 の型）、hypothesis（性質テスト、dev に追加）。LLM・adapters・ネットワーク・時刻に依存しない。

**Spec:** `design/2026-10-05-team-knowledge-registry.md` 4 章（4.1–4.3）、5.1

## Global Constraints

- Task 0 の契約（`domain/uml.py` の名前・欄）は変えない。変える必要が出たら止めて報告する
- `spec/uml/` は LLM・`adapters`・`google.*`・`agent`・`api`・`db` を import しない（`tests/unit/conformance/test_import_boundaries.py` に `spec/uml` を足す）
- 対応しない構文はエラー。明示的に無視するのは `grammar.md` の「無視する要素」の一覧だけ
- IR の式を eval しない。ガードは自前の再帰下降で `Expr` にする
- Conventional Commits、末尾に `(#105)`。push しない

## 文法の決定（詳細は `src/speclino/spec/uml/grammar.md`）

- 図の ID・入口の操作・`closed`・状態を持つ属性は、コードブロック先頭の `%%@ key: value`（Mermaid ではコメントなので描画に影響しない）で宣言する
- ガードの列挙値は `型名.値`（例 `OrderStatus.PENDING`）。名前空間の無い名前はエラー（自然言語のガードを拒否）
- `ir_hash` は `source_hash`・`ir_hash`・span の行と列を除いた正規 JSON のハッシュ（意味のハッシュ）。往復の等価もこの正規形で比べる
