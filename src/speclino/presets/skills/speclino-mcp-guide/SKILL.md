# SpecLino 開発・仕様作成ガイド

SpecLino MCP サーバーのツール群を活用し、MECE（漏れなく・重複なく）な仕様作成から実装・検証までを一貫して進めるための統合ガイドラインです。

## 1. 仕様設計の基本原則

### ファイル構成・分割方針
仕様書は単一ファイルにまとめず、段階や機能ごとに独立した Markdown ファイルとして管理します。

- **要求仕様書（Requirements Specification）**: システム全体の目的・背景・ビジネス要求を定義する独立ファイル。
- **要件定義書（Requirements Definition）**: システム全体の機能・非機能要件、制約条件を定義する独立ファイル。
- **詳細設計書（Detailed Design）**: 機能（フィーチャー/モジュール）単位で独立したファイル（例: `design-<feature-name>.md`）を作成し、モジュール構成・インターフェース・データ構造を完結して記述。

### 構成原則（3階層）
1. **要求仕様**: 背景・目的、対象ユーザー、ユースケース、提供価値
2. **要件定義**: 機能要件（入力・処理・出力）、非機能要件、制約条件
3. **詳細設計（機能単位）**: スコープ・責務、モジュール構成、インターフェース定義、データモデル

### モデリング・作図基準（Mermaid）
構造と振る舞いは Markdown 内で標準レンダリング可能な Mermaid で記述します。

- **振る舞い（動的側面）**:
  - シーケンス図（`sequenceDiagram`）: コンポーネント間連携、メッセージ送受信、非同期通信
  - 状態遷移図（`stateDiagram-v2`）: 状態遷移、トリガーイベント、ガード条件
  - フローチャート（`flowchart TD/LR`）: 業務フロー、処理分岐、例外ルート
- **構造（静的側面）**:
  - クラス図（`classDiagram`）: クラス/モジュールのインターフェース、型定義、関係性
  - ER図（`erDiagram`）: エンティティ関係、データモデル

## 2. 開発ライフサイクルと運用プラクティス

各フェーズにおいて、仕様作成基準の遵守と適切な MCP ツールの呼び出しを行います。

### フェーズ 1: 現状把握・仕様参照
- **仕様・指示書の確認**: 対象リポジトリの既存仕様（`spec:*`）や共通指示（`instructions:*`）の参照ツールを優先して使い、前提知識と既存設計思想を把握する。
- **重複・矛盾の回避**: 新規作成前に既存仕様との重複や方針の齟齬がないか確認する。

### フェーズ 2: 仕様策定・構造化
- **仕様の構造化**: 3階層原則および機能単位の分割方針に従い、仕様作成機能を用いて受け入れ基準や制約事項を明確に落とし込む。
- **作図の適用**: 複雑なロジックやデータ関係には Mermaid 図を組み込み、可視化する。

### フェーズ 3: 実装・段階的検証
- **ツールの使い分け**: 仕様に基づき、目的に合致した最小限のツールを順序立てて呼び出す。
- **ステップごとの検証**: 一度に広範な変更を行わず、ステップ単位でツールの実行結果やテスト結果を確認して進める。

### フェーズ 4: 記録・差分提示
- **差分と変更意図の明示**: 利用者が採否を判断しやすいよう、変更点・テスト結果・変更意図を明確に報告する。

## 3. 作成・検証チェックリスト

- [ ] 仕様書が段階および機能単位で適切にファイル分割されているか
- [ ] 要求仕様・要件定義・詳細設計の対応関係とトレーサビリティが確保されているか
- [ ] 各機能のスコープに漏れや重複（MECE）がないか
- [ ] Mermaidコードに構文エラーがなく、正しく表示されるか
- [ ] 図と本文の記述に矛盾や乖離がないか
- [ ] エラーハンドリングおよび例外フローが明記されているか
- [ ] MCPツールの実行結果およびテストによる段階的な検証が完了しているか
