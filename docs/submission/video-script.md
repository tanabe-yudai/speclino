# デモ動画の台本（3 分）

対象: 第5回 Agentic AI Hackathon with Google Cloud の審査員。伝えること:
「チームがエージェントに渡す知識を SpecLino で管理し、配り、守られていることをゲートで保証し、観測できる」。

- 画面は本番の SpecLino（ログイン済みのテストアカウント）と、GitHub の PR、手元の端末の 3 つ
- 題材は [examples/shop/](../../examples/shop/)、操作の手順は [docs/demo-knowledge-registry.md](../demo-knowledge-registry.md)。
  撮影前にその手順で状態をそろえる（仕様は承認済み、違反を含む PR は作成済み）
- 時間は目安。ナレーションは 1 秒あたり 6〜7 文字で数えている

| # | 時間 | 画面 | ナレーション |
| --- | --- | --- | --- |
| 1 | 0:00–0:15 | タイトル → 散らばった CLAUDE.md・規約の Wiki・各自のスキルのフォルダ | コーディングエージェントの出来は、渡す知識で決まります。でも規約もスキルも仕様も、リポジトリや各自の手元に散らばっていて、守ったかどうかは誰にも分かりません。 |
| 2 | 0:15–0:30 | SpecLino のホーム → 上部の「知識」 | SpecLino は、チームがエージェントに渡す知識を 1 か所で管理します。規約、スキル、AGENTS.md や CLAUDE.md の指示書、そして仕様の 4 種類です。 |
| 3 | 0:30–1:00 | 知識 → 仕様 → 仕様エディタ。左に Markdown と Mermaid、右に図のプレビュー・正規形・診断 | 仕様は人が読める Markdown と、厳格な UML で書きます。図は決定的な parser が IR に変換します。自然言語のガードや未対応の構文は、黙って捨てずにエラーにします。（ガードを日本語に書き換えて診断が赤くなるところを見せ、戻す） |
| 4 | 1:00–1:15 | 「AI の提案」で差分が出る → 採用 → 正規形の差分 | AI は書き換えを提案するだけです。変換と判定には関わりません。承認者は原文と正規形の差分を見て承認します。 |
| 5 | 1:15–1:30 | 承認 → 改訂の履歴（bundle の世代が進む）、自己承認の印 | 承認のたびに、署名つきのスナップショット、bundle ができます。検査も配信も、この番号で固定されます。 |
| 6 | 1:30–1:50 | 端末で `speclino sync` → `.claude/skills/`、AGENTS.md の管理区画、`lock.json` | 各自のエージェントへは、speclino sync と MCP で配ります。スキルと指示書がエージェント本来の場所に書き出され、署名つきの lock が残ります。 |
| 7 | 1:50–2:25 | GitHub の PR → SpecLino / gate が失敗 → run の詳細で VIOLATED と反例、UNKNOWN の理由 | エージェントが書いた PR を、ゲートが検査します。承認済みの仕様に反する経路が、反例つきで「違反」になりました。解析しきれない部分は「未検証」で、偽の「適合」は出しません。必須の要求に未検証が残れば、ゲートは失敗します。 |
| 8 | 2:25–2:40 | LLM 支援の規約の Finding（要確認）→「問題なしとして確定」、または PR コメント `/speclino attest` | 決定的に書けない規約は LLM が支援しますが、判定は常に「要確認」です。人が確定し、その記録はコードの内容に結びつきます。 |
| 9 | 2:40–2:55 | 上部の「可観測性」: 形式化率・対応率・UNKNOWN の内訳・取得の遅れ・規約の推移 | 可観測性の画面では、どの知識がどこまで形式化され、誰がどの版を取り、どの規約が守られているかが見えます。 |
| 10 | 2:55–3:00 | ロゴと URL | 知識を管理し、配り、保証する。SpecLino です。 |

## 撮影のメモ

- 7 の「違反」は、PR を開いた直後ではなく検査が終わった状態から撮る（待ち時間を見せない）
- 3 で書き換えたガードは必ず元に戻してから 4 に進む（承認できない状態のまま撮らない）
- トークン・メールアドレス・GCP のプロジェクト ID が画面や端末に映らないようにする（`SPECLINO_SYNC_TOKEN` は事前に export）
- 字幕は判定の語を画面と同じにする（適合 / 違反 / 未検証 / 要確認）
