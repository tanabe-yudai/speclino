# SpecLino仕様書作成ガイドライン

## 目的
SpecLinoに適合する品質の高い仕様書を作成するための基準と手順を定めます。MECE（漏れなく・重複なく）を徹底し、要求仕様から詳細設計までを一貫して記述します。

## 構成原則
仕様書は以下の階層構造でMECEに整理します。

1. 要求仕様（Requirements Specification）
   - 背景・目的
   - 対象ユーザー・ユースケース
   - 提供価値・ビジネス要求

2. 要件定義（Requirements Definition）
   - 機能要件（入力、処理、出力の明確化）
   - 非機能要件（性能、セキュリティ、可用性など）
   - 制約条件

3. 詳細設計（Detailed Design）
   - モジュール/コンポーネント構成
   - インターフェース定義（API、データ型）
   - データモデル・ストレージ設計

## UMLモデリング基準
プログラムの構造および振る舞いは、テキストベースのUML（PlantUML / Mermaid）を用いて明瞭に表現します。

- 振る舞い（動的側面）：
  - シーケンス図（コンポーネント間の相互作用、同期/非同期呼び出し）
  - ステートマシン図（状態遷移、イベント、ガード条件）
  - アクティビティ図（複雑な業務フロー、分岐処理）
- 構造（静的側面）：
  - クラス図 / コンポーネント図（インターフェース、依存関係、データ構造）

## 作成・検証チェックリスト
- [ ] 各機能・スコープに漏れや重複（MECEの観点）がないか
- [ ] 要求仕様、要件定義、詳細設計の対応関係が追跡可能か
- [ ] 図とテキストの記述に乖離がないか
- [ ] エラーハンドリングおよび例外フローが明記されているか
