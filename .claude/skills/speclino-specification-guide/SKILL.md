# SpecLino仕様書作成ガイドライン

## 目的
SpecLinoに適合する品質の高い仕様書を作成するための基準と手順を定めます。MECE（漏れなく・重複なく）を徹底し、要求仕様から詳細設計までを一貫して記述します。

## ファイル構成・分割方針
仕様書は単一ファイルにまとめず、段階や機能ごとに独立したMarkdownファイルとして作成・管理します。

- 要求仕様書（Requirements Specification）：システム全体の要求・目的を定義する独立ファイル
- 要件定義書（Requirements Definition）：システム全体の機能・非機能要件を定義する独立ファイル
- 詳細設計書（Detailed Design）：**機能（フィーチャー/モジュール）単位**で独立したファイルを生成
  - 例: `design-<feature-name>.md`
  - 各機能の詳細設計書内で、モジュール構成・インターフェース・データ構造を完結して記述する

## 構成原則
仕様書は以下の階層構造でMECEに整理します。

1. 要求仕様（Requirements Specification）
   - 背景・目的
   - 対象ユーザー・ユースケース
   - 提供価値・ビジネス要求

2. 要件定義（Requirements Definition）
   - 機能要件（入力、処理、出力の明確化）
   - 非機能要件（性能、セキュリティ、可用性など）
   - 制約条件

3. 詳細設計（Detailed Design / 機能単位）
   - 対象機能のスコープ・責務
   - モジュール/コンポーネント構成
   - インターフェース定義（API、データ型）
   - データモデル・ストレージ設計

## モデリング・作図基準（Mermaid）
プログラムの構造および振る舞いは、Markdown内で標準レンダリング可能な Mermaid を用いて表現します。

- 振る舞い（動的側面）：
  - シーケンス図（`sequenceDiagram`）：コンポーネント間の相互作用、メッセージ送受信、非同期通信
  - 状態遷移図（`stateDiagram-v2`）：状態の変化、トリガーイベント、ガード条件
  - フローチャート（`flowchart TD/LR`）：業務フロー、処理分岐、例外ルート
- 構造（静的側面）：
  - クラス図（`classDiagram`）：モジュール/クラスのインターフェース、型定義、関係性
  - ER図（`erDiagram`）：エンティティ関係、データモデル

## 作成・検証チェックリスト
- [ ] 仕様書が段階・機能ごとに独立したファイルとして分割されているか
- [ ] 詳細設計が機能単位で過不足なく定義されているか
- [ ] 各機能・スコープに漏れや重複（MECEの観点）がないか
- [ ] 要求仕様、要件定義、詳細設計の対応関係が追跡可能か
- [ ] Mermaidコードが構文エラーなく正しくレンダリングされるか
- [ ] 図とテキストの記述内容に乖離がないか
- [ ] エラーハンドリングおよび例外フローが明記されているか
